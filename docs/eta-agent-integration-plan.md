# RikkaHub Eta Agent 集成总纲

## 0. 项目目标

在不破坏原版 RikkaHub 能力的前提下，形成完整产品组合：

> 原版 Rikka + Eta Agent + Root + 设备工具 + 无障碍 + 浏览器 + Rikka 原有 Skills/MCP/Memory

核心原则：能力分层、最小权限、显式审批、可取消可恢复、证据优先、集中测试。

## 1. 基线与兼容性

- 保留原版 RikkaHub 的聊天、模型、Provider、Workspace、搜索、WebView、设置和数据迁移。
- 保留并验证原有 Skills、MCP、MCP OAuth、Memory、Local Tools、Workspace Tools。
- Eta 能力作为新增工具层接入，不复制或绕过原有 GenerationHandler 工具循环。
- 所有新增工具必须能在模型不支持工具调用时安全降级。
- 升级、降级、旧数据读取和默认设置必须兼容。

## 2. 总体架构

1. Agent 编排层：沿用 ChatService → GenerationHandler → Tool loop。
2. 工具注册层：统一注册、命名、Schema、审批、执行、结果序列化。
3. 能力适配层：设备、Root、无障碍、浏览器、文件和媒体等具体实现。
4. 安全策略层：权限检查、危险操作分类、审批、超时、取消、审计事件。
5. 数据与持久化层：设置、任务状态、记忆、Skill、MCP 配置和会话消息。
6. UI 层：能力开关、权限状态、审批卡片、运行状态、错误和恢复入口。

### 统一工具契约

每个工具必须定义稳定名称和 Schema、风险等级、所需权限、审批策略、超时/取消/并发策略、结构化结果/错误码、大输出分页或截断规则，以及重试和幂等性。

## 3. 能力范围

### 3.1 Eta Agent 基础

- 多轮对话和多步工具调用；
- 流式文本、reasoning、summary、加密 reasoning 的正确保存和回传；
- 工具调用中断、恢复、拒绝、失败和超时；
- 工具结果写回后继续生成；
- 前后台切换、通知和取消；
- 统一错误和状态展示。

### 3.2 Root

- `status`、`run`、`start/read/close`；
- stdout/stderr、退出码、超时、输出上限；
- 进程归属证明、超时清理和取消隔离；
- 默认关闭、危险操作审批；
- 禁止未明确授权的修改、删除、刷写和隐私读取。

### 3.3 设备工具

优先只读：时间、时区、位置、电池、内存、存储、系统版本、网络、Wi‑Fi、蓝牙、通知、应用使用情况、设备环境、相册、音频、录音、文件、下载、日历、联系人、通话、短信、健康摘要、剪贴板历史。

受控写入：音量、媒体控制、闹钟、计时器、Wi‑Fi/蓝牙开关、系统设置、创建日历、发送消息和其他外部副作用；高风险操作必须审批。

### 3.4 无障碍

- 屏幕观察与 UI 树读取；
- 节点点击、区域点击、长按、输入、滑动、滚动；
- 严格绑定 observation_id；节点过期、动作未知、方向错误时重新观察；
- Canvas/地图/图片/二维码等视觉场景按需截图；
- 无障碍不可用或修复超时必须明确失败，禁止盲目重放。

### 3.5 浏览器

- 导航、后退、前进、刷新；
- 正文提取、分页读取、页面信息、元素查找；
- 点击、输入、滚动、等待页面或选择器、截图；
- 外部 URI 与离屏 Agent 浏览器严格区分；
- 登录、付款、提交、删除等高风险动作需要审批。

### 3.6 Skills / MCP / Memory

- Skills：沿用 SkillManager、启用列表、Skill 工具注入和资源读取；
- MCP：沿用配置、OAuth、SSE/Streamable HTTP、工具发现与调用；
- Memory：保留助手级和全局记忆、增删改工具、提示注入和持久化；
- 新工具不能覆盖同名工具，也不能改变旧工具 Schema 语义。

## 4. 实现阶段

### 阶段 A：契约与基础设施

统一 ToolCapability、ToolRisk、ToolResult、ToolError；统一审批、权限、取消、超时、分页和审计接口；接入 ChatService；补齐测试夹具和假实现。

### 阶段 B：Root 完整化

补齐长任务状态、缓存清理、并发限制、超时与取消；完善设置页、权限状态和审批交互；增加 Controller、Tool、Service 集成测试。

### 阶段 C：设备工具

按只读 → 低风险写入 → 高风险副作用实现；明确 Android 权限、空数据和不可用行为；增加版本兼容和脱敏处理。

### 阶段 D：无障碍

建立观察快照模型和动作执行器；严格处理 observation_id、节点过期和失败状态；增加 UI 树、截图、输入和动作回归。

### 阶段 E：浏览器

建立离屏浏览器适配器；实现正文、元素和交互工具；增加加载、超时、登录和高风险操作策略。

### 阶段 F：整合与兼容

将所有能力接入统一注册层；验证 Skills/MCP/Memory 共存；完善设置、通知、会话恢复、迁移和文档。

## 5. 测试策略：集中测试

开发期间先做静态检查、编译级检查和本地单元测试；连续完成一个阶段的大部分代码后再运行一次完整 CI；不因单个小改动反复构建 APK；只有涉及真实设备行为时才安装 APK。

最终集中测试顺序：原版 Rikka 核心 → Eta 对话/reasoning → Skills/MCP/Memory → Root → 设备工具 → 审批和副作用 → 无障碍 → 浏览器 → 取消/超时/权限不足/前后台 → 数据迁移和最终 APK。

通过标准：无崩溃、无静默失败、无未授权副作用；结果可解释、可追踪、可恢复；原版功能和数据兼容；CI、APK 和真实设备集中回归全部通过，并记录版本、提交、设备状态、结果和已知限制。
